# Implementation Plan: Weekly Workout Planner

**Branch**: `007-weekly-planner` | **Date**: 2026-04-19 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/007-weekly-planner/spec.md`

## Summary

Users can create named weekly workout plans, either by importing multi-day program text or by manually building days. Each plan day is assigned to one or more days of the week. When a plan is active, "Today's Session" on the Dashboard shows the planned workout for today's weekday instead of the auto-generated session. Rest days show a fallback banner. Plans are stored locally via two new SwiftData `@Model` types (`WorkoutPlan`, `PlanDay`), with exercises stored as a `Codable` struct array. No new architectural patterns are introduced.

### Key Design Decisions

**WorkoutPlan → PlanDay relationship**: `@Relationship(deleteRule: .cascade)` parent→child. Deleting a plan cascades to all its days automatically.

**PlanExercise as Codable struct**: Exercises within a day are a value snapshot — not live-linked to the `Exercise` library. Stored as `[PlanExercise]` on `PlanDay`.

**Weekday convention**: `Calendar.weekday` integers (1 = Sunday … 7 = Saturday). Displayed using `Calendar.current.shortWeekdaySymbols` for locale awareness. Stored as `[Int]` on `PlanDay`.

**Dashboard lookup** (no new architecture):
```swift
// DashboardView — computed properties only
var activePlan: WorkoutPlan? { allPlans.first(where: { $0.isActive }) }
var todayPlanDay: PlanDay? {
    let weekday = Calendar.current.component(.weekday, from: Date())
    return activePlan?.days.first(where: { $0.weekdays.contains(weekday) })
}
```

**RoutineDetailView reuse**: `PlanExercise` entries converted to synthetic `Exercise` objects (sets → `value * 45` nominal seconds; seconds → `value`). Passed as `allExercises` parameter — zero changes to `RoutineDetailView`.

**Import reuses WorkoutParser**: `WorkoutParser.parse(text:)` already returns `[ParsedDay]`. Map each to a `PlanDay` with empty `weekdays`; user assigns weekdays in `PlanEditorView` before saving.

**Activation mutex**: When activating a plan in `WeeklyPlannerView`, iterate all plans in the model context, set `isActive = false` on all, then `isActive = true` on the target. SwiftData autosave handles atomicity.

**Schema migration**: Both new `@Model` types are purely additive (no existing model changes). No `SchemaMigrationPlan` required.
