# Implementation Plan: Injury & Custom Workout Builder

**Branch**: `006-injury-custom-workout` | **Date**: 2026-04-19 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/006-injury-custom-workout/spec.md`

## Summary

Users can indicate one or more active injuries in their profile; the daily generated workout automatically excludes contraindicated exercises. Users can also bypass the auto-generated session and build a custom workout by multi-selecting from the four exercise categories (Stretching, Breathing, Bodyweight, Balance) and adding their own named exercises. All data is stored on-device via SwiftData.

## Technical Context

**Language/Version**: Swift 5.9+ (Xcode 26.2 / toolchain 2630)  
**Primary Dependencies**: SwiftUI, SwiftData, PhotosUI, AVFoundation, UserNotifications (all system — zero third-party)  
**Storage**: SwiftData — existing models `UserProfile`, `Exercise`, `Routine`; new model `CustomExercise`  
**Testing**: XCTest (`inMemory: true` model containers)  
**Target Platform**: iOS 17.0+  
**Project Type**: Mobile app (single-user, on-device)  
**Performance Goals**: Standard 60 fps SwiftUI rendering; session build completes instantly (<10 ms for ≤100 exercises)  
**Constraints**: Offline-first (no network); zero new SPM dependencies; schema changes must be additive (default values)  
**Scale/Scope**: Single user; ~61 seeded exercises + unbounded custom exercises

## Implementation Phases

### Phase 1 — Data Model (no UI changes)

1. Add `InjuryType` enum to `Models.swift`
   - `String`-backed, `CaseIterable`, `Identifiable`, `Codable`
   - Six cases: `.lowerBack`, `.shoulder`, `.knee`, `.wristElbow`, `.ankleFoot`, `.neck`
   - `var displayName: String` and `var icon: String` computed properties

2. Add `CustomExercise` `@Model` to `Models.swift`
   - Fields: `name: String`, `durationSeconds: Int`
   - Register in `dailyApp.sharedModelContainer` Schema

3. Add `activeInjuries: [String] = []` to `UserProfile` `@Model`

4. Add `contraindications: [String] = []` to `Exercise` `@Model`

5. Update `Exercise.seedInitialData` / `migrateData` to populate `contraindications` on all seeded exercises using the `InjuryType` raw values

6. Update `Routine.buildSession` to filter out exercises where `contraindications` intersects with `profile.activeInjuries`

### Phase 2 — Injury UI (Profile)

7. Create `InjuryPickerView.swift`
   - List of all `InjuryType` cases with checkbox-style toggle
   - Writes selected injury raw values to `profile.activeInjuries` via `@Environment(\.modelContext)`
   - `#Preview` block required

8. Modify `ProfileView.swift`
   - Add "Active Injuries" section below gender selector
   - Sheet presentation of `InjuryPickerView`
   - Show active injury tags/chips in collapsed state
   - "None" fallback when `activeInjuries` is empty

### Phase 3 — Custom Workout Builder

9. Create `CustomWorkoutBuilderView.swift`
   - Category multi-select grid (four categories, same icons as `DashboardView`)
   - Greedy-fill preview showing estimated session duration as categories are toggled
   - "My Exercises" section: list of saved `CustomExercise` records (via `@Query`)
   - "Add my own exercise" → inline form with name + duration fields + validation
   - "Build Session" button (disabled if no categories and no custom exercises selected)
   - On confirm: assembles `[String]` of exercise names (category pool filtered by injury + selected custom exercises) and navigates to `RoutineDetailView` with the result
   - `#Preview` block required

10. Modify `ContentView.swift` (`DashboardView`)
    - Add "Build your own" button/link on or below `DailyRoutineCard`
    - `sheet(isPresented:)` presenting `CustomWorkoutBuilderView`

### Phase 4 — Injury feedback in generated session

11. Modify `DashboardView` session generation (in `ContentView.swift`)
    - After filtering, if resulting pool is shorter than the tier's minimum duration, show a non-blocking banner/notice explaining that some exercises were removed due to the user's active injury
    - Use the shortest available safe session rather than an empty/broken one

## Verification

1. **Injury filtering**: Set a shoulder injury in Profile → generate daily session → verify no shoulder-contraindicated exercises appear in the routine.
2. **Injury pool exhaustion**: Set an injury that removes most exercises → verify a shorter safe session is built with an explanatory notice (not an empty or broken routine).
3. **Injury removal**: Clear injury from Profile → generate session → full exercise pool is restored.
4. **Custom builder — category select**: Open builder → select Stretching + Breathing only → confirm → verify `RoutineDetailView` shows only exercises from those two categories.
5. **Custom builder — injury respected**: With active knee injury + knee-contraindicated exercises → open builder → select Bodyweight → confirm → verify knee-contraindicated exercises absent.
6. **Custom exercise add**: Tap "Add my own" → enter name "Physio Hip Rotation" + 60 seconds → save → verify it appears in the session.
7. **Custom exercise validation**: Submit with blank name or 0-second duration → verify error shown, no save occurs.
8. **Custom exercise reuse**: Close and reopen builder → verify previously added custom exercises appear in "My Exercises" list.
9. **Schema registration**: Fresh install and upgrade install both launch without crash; SwiftData container initialises with `CustomExercise` in Schema.
10. **Constitution compliance**: All new views have `#Preview` blocks; no UIKit; no third-party packages.
